# Navigation Design

## Navigation Principles

1. **Mirror the architecture** — The sidebar reflects the platform layers from bottom to top: Runtime → Ledger → Analytics → Evidence → Recommendations → Experiments → Configuration → Operations → Automation.
2. **Optimize for engineers** — Every item is a noun (Findings, Recommendations, Experiments). No verbs. No branding fluff.
3. **Two levels max** — Top-level nav items may expand to a flat list of sub-items. No nested flyouts, no mega-menus.
4. **Context over chrome** — Navigation is deliberately sparse. Screen real estate belongs to content.
5. **Keyboard-first** — Every nav item is reachable via keyboard (⌘K palette or numbered shortcuts).
6. **State-preserving** — Navigating away and back restores the previous view state (scroll position, filters, selected item).

## Global Search Behavior

- **Trigger**: ⌘K (macOS) / Ctrl+K (Windows/Linux) — always available
- **Scope**: Indexes all artifact types, capabilities, configs, users
- **Behavior**:
  1. Typing shows instant results grouped by artifact type
  2. Results include: artifact ID, title, type, timestamp, capability
  3. Selecting a result navigates to the artifact detail page
  4. Pressing ↓ continues to navigate results; Enter selects
  5. Escape closes the palette without navigating
- **Advanced**:
  - Prefix search with `type:artifact_type` to filter (e.g., `type:recommendation`)
  - Prefix with `capability:name` to scope to a capability
  - Prefix with `id:` to search by artifact ID

## Breadcrumb Strategy

Breadcrumbs appear in the top bar and follow this pattern:

**Home > Section > Page > [Item Name]**

Examples:

```
Home > Observe > Findings > Finding #1024
Home > Analyze > Experiments > A/B Test #47
Home > Govern > Configuration > Snapshot v142
```

- Breadcrumbs are clickable — each segment navigates to that level's listing page
- The final segment (item name) is non-clickable (current page)
- On listing pages (e.g., Findings list), the item name segment is omitted
