# CI/CD Integration

## GitHub Actions Workflow

The project includes a complete CI/CD pipeline defined in `.github/workflows/rag-benchmark.yml`.

### Triggers

| Event | Behaviour |
|---|---|
| `push` to `main`/`master`/`develop` | Full benchmark with `--compare latest` |
| `pull_request` to `main`/`master`/`develop` | Full benchmark with PR comment |
| `schedule` (nightly 02:00 UTC) | Matrix run across all 3 retriever modes |
| `workflow_dispatch` (manual) | Custom retriever, dataset, or compare target |

### Services

- **PostgreSQL** — `ankane/pgvector:latest` with pgvector extension
- **Redis** — `redis:7-alpine` for caching and tracing

Both services have health checks before the benchmark begins.

### Pipeline Steps

1. **Checkout** — action/checkout@v4
2. **Setup Python** — Python 3.11 with pip cache
3. **Verify install** — `python scripts/verify_install.py`
4. **Install dependencies** — from `requirements-lock.txt`, plus `ragas`
5. **Write .env** — from GitHub secrets (OPENAI_API_KEY, etc.)
6. **Start backend** — `uvicorn` with wait loop (up to 60s)
7. **Rebuild search index** — `rag index rebuild`
8. **Run benchmark** — `--ci --pr-summary --compare latest`
9. **Upload artifacts** — full report bundle, 30-day retention
10. **Post PR comment** — benchmark results as markdown table
11. **Check gates** — exit 1 on FAIL, exit 0 on WARNING or PASS

### PR Comments

When the workflow runs on a PR, it posts a comment with:

- Dataset and retriever info
- Pass rate, latency, weighted pass rate
- Gate status (PASS/WARNING/FAIL with per-metric details)
- Comparison table vs baseline (metric deltas with +/- icons)

The comment is generated by `_generate_pr_summary()` in the CLI module and posted via `actions/github-script@v7`.

### Matrix Job (Nightly)

The `benchmark-matrix` job runs all three retriever modes in parallel:

```
vector ──> benchmark_vector.json
bm25   ──> benchmark_bm25.json
hybrid ──> benchmark_hybrid.json
```

This is useful for tracking performance differences across retrieval strategies over time.

### Required Secrets

| Secret | Purpose |
|---|---|
| `OPENAI_API_KEY` | Embeddings + LLM |
| `TAVILY_API_KEY` | Web search fallback |
| `LANGCHAIN_API_KEY` | LangSmith tracing |

## Quality Gates

### Three-Level System

| Status | Meaning | CI Action |
|---|---|---|
| PASS | All metrics above threshold | Allow merge |
| WARNING | Metrics within 2% of threshold | Allow merge + notify |
| FAIL | Metrics below threshold | Block merge (exit 1) |

### Default Thresholds

Configured in `pipeline_config.yaml`:

```yaml
evaluation:
  minimum_faithfulness: 0.93
  minimum_answer_relevancy: 0.92
  minimum_context_precision: 0.90
  minimum_context_recall: 0.90
  maximum_latency_ms: 2500
  warning_zone: 0.02
```

## Local CI Simulation

```bash
# Run benchmark in CI mode
rag benchmark thinking_fast_and_slow --ci

# Run with comparison
rag benchmark thinking_fast_and_slow --ci --compare latest

# Check exit code
echo $?
```

## Artifacts

Each CI run produces a downloadable artifact:

```
benchmark-<dataset>-<retriever>-<sha>/
    summary.json
    results.json
    report.html
    metadata.json
    analytics/
    comparison/
    failures/
    README.md
    benchmark_result.json       # Raw CI JSON output
    pr_summary.md               # PR comment text
```

Artifacts are retained for 30 days.
